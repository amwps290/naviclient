# 逐字歌词可行性与实现方案

日期：2026-11-13。范围：分析现有客户端、核对公开接口，提出开发方案；已完成的首版内容与验证结果见文末。

## 结论

可以实现，不需要更换 Rust / GPUI / rodio 技术栈。建议先支持原生 OpenSubsonic `songLyrics v2` 和网易云 YRC，再补充酷狗 KRC。首版效果为：当前歌词行中的字、词或音节按真实时间逐步变色，保留逐行滚动、点击跳转、翻译与单曲偏移。

“逐字”的粒度取决于来源：中文可能按字，英文可能按词或音节。普通 LRC 只有行开始时间，不能准确还原每个字的演唱时间；没有逐字数据时继续使用逐行高亮。首版不引入从音频自动识别或强制对齐歌词的模型。

## 接口核对与实际样本

### 原音乐源：OpenSubsonic v2

已核对公开 [songLyrics 扩展规范](https://opensubsonic.org/docs/extensions/songlyrics/)、[getLyricsBySongId](https://opensubsonic.org/docs/endpoints/getlyricsbysongid/) 和 [cueLine](https://opensubsonic.org/docs/responses/cueline/)：

- v1 是逐行歌词；v2 新增字 / 词 / 音节时间和歌词类型。
- 只有显式传入 `enhanced=true` 才返回增强字段；默认响应保持 v1。
- `cueLine` 是与 `line` 并列的结构，通过 `index` 关联原行。
- `cueLine.value` 是自身可显示的正文，嵌套 `cue` 提供时间和文字范围。
- `byteStart` / `byteEnd` 是最终正文的 UTF-8 字节偏移，两端均包含。不能先 trim 或 Unicode 规范化正文再使用这些偏移。
- 同一行可能有多个演唱者的 cueLine；应按 `agents[].role == main` 选择主唱，保留原 `line` 作为组合正文的逐行回退。
- `kind` 区分 `main`、`translation`、`pronunciation`。v2 不能沿用仅按语言不同就判断翻译的规则。
- 时间均为歌曲内的毫秒位置，`offset` 同时作用于行和 cue 的开始 / 结束时间。

Navidrome 开发分支已能构造这些增强响应，核对版本为 [94a6e59](https://github.com/navidrome/navidrome/blob/94a6e59feee40c993c491ad19b61ed9c3fbc558e/server/subsonic/lyrics.go)。这不表示用户当前部署的版本一定支持，也不表示每首歌都有逐字数据。客户端应使用已有的能力发现结果，不按服务端名称猜测支持情况。

### 网易云：已验证可返回 YRC

公开新版路径 `/api/song/lyric/v1` 在本次匿名 GET 样本中返回 `code=200`，同时包含 `lrc` 和 `yrc`。查询 ID `66842`（此前项目研究中的《十年》/ 陈奕迅样本），检测到 38 个 YRC 时间行和 294 个带时间的片段，最后一个时间行结束于 183050 ms。

请求使用 `id`、`cp=false` 及 `tv/lv/rv/kv/yv/ytv/yrv=0`，带网易云主页 Referer。旧路径 `/api/song/lyric` 保留为逐字不可用时的兼容路径。接口形式可参考公开 [lyric_new.js](https://github.com/neteasecloudmusicapienhanced/api-enhanced/blob/master/module/lyric_new.js)。

YRC 行格式为 `[行开始毫秒,行持续毫秒](片段开始毫秒,持续毫秒,标记)文字...`。片段开始是歌曲内的绝对时间，不应再加一次行开始时间；格式核对参考 [公开 YRC 解析实现](https://github.com/Steve-xmh/applemusic-like-lyrics/blob/main/packages/lyric/src/formats/yrc.ts)。

这个样本证明接口能返回真实逐字时间结构，未逐首播放音频核对，也不能据此推断完整曲库覆盖率或长期可用性。

### 酷狗：已验证可下载 KRC 文件

沿用现有 `/search` 获取候选和临时 `accesskey`，将 `/download` 的 `fmt` 改为 `krc`，本次《海阔天空》/ Beyond 候选 ID `248314971` 返回 `status=200`；Base64 解码后为 610 字节，文件头是 `krc1`。

本次只验证到了 KRC 文件头，尚未完成解压后正文与音频同步核对。接入还需要实现 KRC 文件识别、格式规定的 XOR 还原、zlib 解压以及文本时间解析；设置解压后的大小上限。

同次搜索的候选时长包含 25 秒、30 秒、约 205 秒、317 秒与 322 秒。下载的第一个候选是 25 秒片段，不可作为完整版歌曲的自动匹配依据。项目现有严格歌名 / 歌手 / 版本 / 时长匹配仍然必要，不能直接使用第一条候选。

### LRCLIB 与扩展格式

保留当前逐行服务。项目 2026-11-09 的研究记录过 `lyricsfile` / `hasWordSync` 扩展，本次访问 LRCLIB 文档遇到 TLS 连接失败，未重新验证字段、格式和逐字样本。因此不将其纳入首版逐字数据承诺，也不将 LRCLIB 判定为永远只能逐行。

增强 LRC 可作为纯解析能力补充；本地导入、TTML、QRC、其他 Lyricsfile 格式留到后续，不作为首版依赖。

## 内部数据设计

保留原有 `LyricLine.text` 和 `translation`，将逐字内容作为可选扩展，避免破坏普通歌词和原音乐源的回退显示。建议新增以下结构，示例仅表达模型，实际命名可在实现时调整：

```rust
struct LyricSegment {
    // 内部统一为 UTF-8 字节的半开区间。
    text_range: std::ops::Range<usize>,
    start_ms: u64,
    end_ms: Option<u64>,
}

struct WordTimedLine {
    text: String,
    start_ms: u64,
    end_ms: Option<u64>,
    segments: Vec<LyricSegment>,
}

// LyricLine 新增：
// end_ms: Option<u64>
// word_timing: Option<WordTimedLine>
```

逐字正文单独保存，是因为 OpenSubsonic 主唱 `cueLine.value` 可能不同于组合 `line.value`。有有效逐字数据时绘制前者；关闭逐字或数据无效时显示原逐行正文。

不同格式进入同一模型：YRC 使用绝对片段时间；KRC 解析时将行内相对时间转为歌曲绝对时间；增强 LRC 根据实际标签变体解析。保留空格、标点和未带时间的文字，不以简单 `.chars()` 拆分后的索引代替字节范围。

OpenSubsonic 范围转换为 `byteStart..byteEnd + 1`，检查溢出、正文边界、UTF-8 边界及对应文字。必须先按原 `line` 索引关联 cueLine，再过滤空行，否则 index 会错位。异常 cue 降级到该行的普通显示，不能让一条错误数据导致整首歌失败。

来源结束时间和推断结束时间应区分。来源提供明确行结束时保留；缺失时最多根据下一片段 / 下一行推断展示边界。最后一个片段无法安全推断结束时间时，在开始时整体变色，不假造拖音时长。零时长片段作为瞬时标记，不参与除法。

## 获取、策略与缓存

1. 原音乐源支持 v2 时，使用 `getLyricsBySongId?id=...&enhanced=true`。仅支持 v1 时保持现有请求。v2 请求失败或响应缺少增强字段时回退 v1，保留旧接口作为最终回退；能力未知时不要求额外网络探测才能使用旧路径。
2. 网易云在当前已启用来源范围内尝试新版，保留 YRC 和 LRC 两种正文。YRC 缺失、解析无效或新版请求失败时使用可用 LRC；控制总请求预算，避免新版失败后又进行无限重试。
3. 酷狗后续优先下载 KRC，失败时尝试 LRC，下载键仍只在请求过程中使用。
4. `Record` 新增可选的逐字正文及格式字段，并通过 `serde(default)` 兼容旧缓存。保留现有 LRC 作为回退，不把 YRC 内容塞进只按 LRC 解析的 `synced_lyrics`。
5. 旧缓存缺少逐字内容时仍可读；用户搜索 / 刷新时升级该记录，避免启动后集中重新下载。保持歌曲固定选择、来源身份和原有偏移。格式发生不兼容变化时才进行明确版本迁移，不为增加可选字段清空缓存。

显示模式建议首版提供“自动 / 关闭”：自动使用当前选定文档中的有效逐字时间，没有则逐行显示；关闭回到现有行高亮。手动搜索候选显示“逐字 / 逐行 / 纯文本”，并支持筛选逐字版本。

显示模式与现有“原源优先 / 在线优先 / 仅手动”策略分开。当前自动策略会在先命中的逐行来源停止，因此“自动显示”不等于“自动遍历所有来源找逐字”。首版可通过手动选择逐字候选解决；如需要全自动升级，另加明确的“优先查找逐字版本”偏好，仅在已经启用的来源中查找，先展示可用逐行歌词再尝试升级，且不覆盖用户固定选择。无可信逐字匹配时保留当前文档。

## 显示与播放同步

建议新增 `src/app/player/word_lyrics.rs`，封装 GPUI 逐字文本绘制，不把大量绘制细节继续堆进 `now_playing.rs`。

- 当前行尚未演唱的片段使用弱化文字色，已唱完片段使用强调色，当前片段按真实持续时间逐步填充。
- 对 `end > start` 的片段，填充比例为 `clamp((position - start) / (end - start), 0, 1)`；必须先处理早于开始、缺失结束和零时长情形。
- 使用 GPUI 文字 shaping 结果进行完整文本布局，再按片段范围裁剪叠绘强调色。多行换行按实际布局处理，各片段分别计算范围，不用整行总宽度乘歌曲进度。
- 缓存布局，键包含正文 / 文档版本、字体、字号、字重、可用宽度和显示缩放；每帧只更新颜色和裁剪范围。英文连字、组合字符及字体回退必须使用字形簇映射，不能按字符数估算像素宽度。
- 第一版可先按整个片段切换颜色，验证完整数据路径，再加入片段内部连续填充。不要为每个汉字创建独立布局组件，避免破坏英文排版并产生过多界面节点。
- 逐字进度始终由歌曲位置计算。仅换行时触发滚动；切字不触发滚动。保留当前行强调、翻译、点击跳转与已有过期请求检查。

音频线程与播放页现在约 20 Hz，足够首版按片段变色，但连续扫色可能看起来有台阶。后续将活跃歌词组件提升到约 60 Hz 局部刷新；不把所有页面和音频工作循环统一提高到 60 Hz。

平滑时钟应以带采样时刻的实际音频快照为基准，在快照之间有限外推，并定期校正。暂停、拖动、切歌、输出断开、缓冲停滞和连续不前进的快照要冻结或重置；快照过期后停止外推。歌词不能仅靠从点击播放起累计 `Instant` 推进，否则暂停和缓冲会失步。

文件自带 offset 和歌曲手动 offset 各应用一次，同时调整行与片段的开始 / 结束时间。可以复用当前 `Document::display_lyrics()` 的统一转换层；纯文本模式同时禁用行和逐字同步。精确行结束后停止扫色，间奏行为保持稳定；没有精确结束时使用明确的回退规则。

## 开发顺序与验收

### 第一阶段：模型与原生数据

新增时间模型与统一验证，接通现有 `enhanced_lyrics` 能力，解析 v2 `kind` / `cueLine` / 主唱。用自写短歌词夹具验证范围、偏移与 v1 回退，不依赖在线服务。

验收：旧逐行显示与翻译保持可用；具备 v2 数据的歌曲能获得有效时间片段；未升级的服务端仍正常加载歌词。

### 第二阶段：首个可用逐字闭环

接入网易云 YRC、扩展缓存、增加逐字候选标识和显示模式，先实现片段切色。使用已验证 ID 再做实际歌曲播放验收，确保不是只验证接口成功。

验收：播放、暂停、继续、前后拖动、快速切歌、调整偏移均正确；无 YRC 时继续显示 LRC；关闭联网后已缓存的逐字固定选择仍可显示。不能仅以 `HasYrc=true` 作为完成。

### 第三阶段：连续填充与布局性能

实现文字裁剪填充、布局缓存和活跃元素刷新；验证中文、英文、日文、标点、重复词、窄窗口换行和高 DPI。重点查看拖音、间奏、暂停后恢复是否有跳动，后台隐藏时是否停止动画。

验收：连续填充的平滑度、CPU 与布局开销达到实际设备可接受水平；字体 / 窗口尺寸变化不会让强调层偏离原文。

### 第四阶段：扩展覆盖

完成 KRC 解码与版本匹配验收，补充增强 LRC。再独立评估本地导入、TTML、LRCLIB 扩展和多人声显示。

解析与时间计算需要有意义的单元测试：绝对 / 相对时间、UTF-8 范围、重复文字定位、零时长、缺失结束、空行索引、异常时间、双重偏移防护。API 用现有本地 HTTP 测试框架覆盖 v2 回退、YRC 缺失和错误正文；缓存覆盖旧记录恢复与新记录往返。真实接口检查单独运行，不作为日常测试依赖。

## 风险边界

最主要的不确定性是歌词版本、覆盖率与第三方接口稳定性；绘制和时间模型属于客户端可控的工程工作。本文已验证网易云时间结构、酷狗 KRC 文件头及公开 v2 合约，未连接用户实际 Navidrome 服务端，也未完成逐首音频核对。

推荐优先交付“原生 v2 + 网易云 YRC + 自动逐行回退”的可用版本，再扩展格式和复杂动画。音频识别 / 强制对齐涉及额外模型、资源与质量评估，应作为独立功能评估。

## 首版实施结果

已接通原生 OpenSubsonic v2 与网易云 YRC，保留旧接口和逐行回退。增加精确 UTF-8 范围验证、行结束时间、统一偏移、YRC 缓存，以及主唱与翻译类型选择。能力发现稍晚返回 v2 时会刷新当前原源自动歌词，用户固定选择不被覆盖。

播放页使用完整文字 shaping 和按时间片段裁剪叠绘，实现连续填色；支持换行、居中、暂停、前后跳转与窗口宽度变化。复用现有 50 ms 更新和 GPUI 字形布局缓存，尚未新增 60 Hz 外推时钟。

逐字显示默认开启，可在设置 → 歌词或播放页歌词菜单关闭。搜索候选标注逐字格式，并可筛选“仅显示逐字歌词”。旧配置和旧缓存保持可读，缓存的逐字固定选择在离线状态下仍可恢复。

验证结果：

- 日常回归 1362 项通过、6 项忽略；1 项未改动的音频测试 `connection_failure_diagnostics_do_not_expose_signed_stream_urls` 在当前 Windows 环境失败，实际分类为 Timeout、预期为 Connect。未为此修改音频代码或放宽该断言。
- 新增歌词解析、原生请求回退、服务路由、偏移、缓存恢复与 GPUI 绘制测试通过。绘制测试覆盖窄窗口换行、暂停位置保持和双向跳转。
- 实际 Rust 客户端重新获取网易云 ID 66842，验证 38 个有效逐字行、294 个时间片段；该真实接口测试单独运行通过。
- 格式检查和 Clippy 通过；Clippy 使用 `-D warnings -A dead_code`，排除 Windows 下原有 `CredentialError::Locked` 未构造警告。
- 本机 HTTP 测试需对 `127.0.0.1,localhost` 设置进程级 NO_PROXY；Windows 凭据测试需在沙箱外运行。

尚未连接用户实际 Navidrome 服务端，也未完成真实音频的逐首人工同步验收。酷狗 KRC、增强 LRC、本地导入、TTML、全自动跨来源寻找逐字版本以及 60 Hz 平滑时钟仍属于后续扩展。
