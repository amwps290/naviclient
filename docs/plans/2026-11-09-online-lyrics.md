# 在线歌词功能方案

日期：2026-11-09。更新：2026-11-11。状态：首版 A–C 已实现，自动回归通过。

目标：让没有原生歌词、歌词错误或时间轴有固定偏差的音乐源，也能使用可选择、可恢复的在线歌词。用户的曲库包含中文和外语歌曲。

附件：[可行性与 API 实测](../research/2026-11-09-online-lyrics-feasibility.md)、[可点击 UI 原型](../prototypes/online-lyrics.html)。原型使用占位歌词，仅演示交互，不连接任何服务。

## 1. 推荐方案

首版接入 LRCLIB，提供自动补缺、手动搜索/更换、单曲时间调整和本地缓存。歌词服务独立于音乐源：Bilibili、Navidrome/OpenSubsonic 以及未来的源都通过同一套歌词流程获得结果。

默认保留原音乐源歌词。用户启用在线服务后，只有原歌词缺失、请求失败或不支持歌词时，才自动查询在线歌词。原歌词存在但内容不正确，由用户通过“搜索 / 更换歌词”纠正；不以“行数少”“没有时间戳”等粗略信号判断其内容一定错误。

首版同时支持“在线优先”和“仅手动搜索”。优先级不能承诺歌词一定正确，因此所有自动匹配都保留更换入口、来源标识和恢复默认行为。

## 2. 已验证的可行性与限制

LRCLIB 无需 API Key，有稳定 v1 检索、按歌曲元数据获取和按记录 ID 获取接口，返回同步 LRC 与纯文本。三首中文、两首英文和一首日文歌曲的在线检索均返回同步歌词候选；《稻香》223 秒精确请求成功，233 秒请求返回预期 404。

这验证了接入可行性，不代表整个曲库的覆盖率或歌词正确率。实际候选有重复歌手、不同专辑、零时长和现场版本，因此匹配和纠错界面是核心功能。

LRCLIB 不保证提供独立的翻译字段。首版继续显示音乐源提供的翻译，不自动翻译在线歌词，也不将两种语言自动拼成双语歌词。逐字卡拉 OK、翻唱变速对齐不在首版范围内。

## 3. 查询与选择规则

### 3.1 明确的三种策略

| 策略 | 行为 |
| --- | --- |
| 原音乐源优先（推荐） | 原歌词可用时直接显示；缺失、不支持或失败时查在线服务 |
| 在线歌词优先 | 先查在线高可信匹配；无匹配、低可信、限流或网络失败时使用原歌词 |
| 仅手动搜索 | 自动加载原音乐源歌词；在线服务只在用户搜索时访问 |

在线服务总开关关闭时，不发出新的第三方请求。已经保存在本地的单曲选择仍能显示，避免“关闭联网”同时导致已下载歌词消失；解除该曲的固定选择使用“恢复自动选择”，可重新下载的自动缓存另外清理。

### 3.2 单曲优先级

先检查当前 `MediaKey` 对应的用户选择，存在且本地正文可用就直接使用；否则读取自动查询缓存，再按照全局策略加载原歌词和在线歌词。

已保存的用户选择不会被后续自动查询、迟到的原音乐源响应或切换设置覆盖。用户点击“恢复自动选择”时，解除该曲的固定选择并重置其偏移，重新按策略加载。

在线请求失败不能清空已经显示的原歌词或用户选择。手动更换失败也应保留当前歌词。

### 3.3 自动匹配

使用歌名、歌手、可信时长以及可用的专辑字段请求 `/api/get`。取得结果后还需核对返回元数据，而非把 HTTP 200 当作匹配正确的证明。

匹配规则：

1. 歌名、歌手采用 Unicode 与空白/标点规范化，英文大小写不敏感；保留语言字符，不用“删掉非英文字符”处理中文和日文。Unicode 规范化不能自动解决简繁体与中外文艺名；首版不猜测未知别名，用户可修改搜索词。
2. 保留现场、翻唱、伴奏、Remix、Acoustic、Radio Edit 等版本信息；候选与曲目版本不一致时，不自动选用。
3. 自动同步匹配需要可信时长，首版采用 ±2 秒的严格筛选。候选时长为 0、视频整体时长或超过接口范围时，不构造高可信结果。
4. 专辑一致可增加可信度；专辑缺失不是报错。存在多个明显不同且可信度接近的候选时，交给用户选择。
5. `/api/get` 无匹配后，可以进行一次结构化 `/api/search`，在本地验证和排序。不能直接取搜索第一条。
6. 同曲、同版本、相近时长且正文一致的重复记录可以折叠；不同歌词正文或不同时间轴仍保留为可选版本。

UI 展示“歌名、歌手一致”“时长相差 1 秒”“专辑不同”等理由，不展示没有经过标定的“99% 正确率”。

### 3.4 Bilibili 与元数据不足

Bilibili 的 UP 主和视频标题只用于预填搜索提示，不能当作歌手与标准歌名。对缺少可信歌手的曲目，首版默认引导手动填写或修改歌名/歌手；不按视频标题第一条结果自动加载同步歌词。

分 P 内容使用当前分 P 时长，并允许修改搜索词；不取整段合集的时长。一段视频包含多首歌曲时，单份歌词不能自动覆盖整段音频，需要后续的分段映射能力。

翻唱、现场有同一首歌的文本时，允许用户选择“按纯文本显示”。固定时间偏移只能纠正整条时间轴的统一偏差，不能修正不同速度、改编段落或删减。

## 4. UI 设计

### 4.1 设置中的“歌词”页

新增独立的“歌词”设置页，将现有播放设置中的“显示翻译”移入该页，避免重复入口。桌面沿用设置左侧导航；窄窗口的导航需要允许滚动或使用选择菜单，避免新增分类后挤压文字。

```text
歌词

在线歌词                           [开关]
启用后会向所选服务发送当前歌曲的歌名、歌手、专辑和时长。

服务                 [ LRCLIB           ▾ ]
获取策略             [ 原音乐源优先       ▾ ]
连接方式             [ 使用系统代理       ▾ ]

显示翻译                           [开关]
仅显示歌词源提供的翻译。

缓存：已保存 128 首 / 2.4 MB          [清理在线缓存]
固定选择与时间调整会保留。
```

- 首次升级默认不启用在线请求；开关启用后使用“原音乐源优先”。
- 服务首版只有 LRCLIB，显示服务名称和“无需账号”。只有接入第二个服务后才需要服务下拉。
- 歌词连接方式独立于正在播放的音乐源，复用现有“使用系统代理 / 直连 / 保存的代理”选项，默认跟随系统。音乐源需要代理，并不意味着歌词服务也需要同一代理。
- 设置修改自动持久化，并给出成功或失败提示；保存失败保持原设置。网络不可用不妨碍保存。
- 清缓存只移除自动下载、可重新获取的正文；固定选择使用的正文与单曲偏移保留。将来需要清理个人选择时提供单独操作。
- 设置页展示的数量和大小来自真实缓存统计；原型中的数字是示意。

### 4.2 正在播放页

保留现有左侧黑胶与歌曲信息、右侧歌词的布局。在歌词标题附近增加来源、格式和操作，主体不因来源更换而变成另一种页面。

```text
歌词                                      [更换] [⋯]
来源：LRCLIB · 同步歌词 · 已手动选择

                 上一行歌词
              当前高亮的歌词
                 下一行歌词
```

来源用人能理解的名称：原音乐源、LRCLIB、已手动选择。本地缓存只表示加载状态，可放在说明或 tooltip 中，不能让来源变成模糊的“缓存歌词”。

菜单包含“搜索 / 更换歌词”“歌词时间调整”“按纯文本显示”“恢复自动选择”。纯文本歌词禁用时间调整和点击跳转；没有个人选择时不展示恢复操作。

即使原音乐源歌词正常，仍显示“更换”，以处理内容错误。服务关闭时点击“更换”可打开说明并引导开启在线服务；没有静默联网。

### 4.3 无歌词与失败状态

| 状态 | 文案与操作 |
| --- | --- |
| 正在查询原歌词 | “正在读取音乐源歌词…”；播放继续 |
| 原歌词缺失后在线查询 | “正在查找在线歌词…”；不显示重连 Toast |
| 已启用在线服务但未找到 | “没有找到匹配的歌词” + “搜索歌词” |
| 元数据不足 | “补充歌名和歌手，搜索在线歌词” + 搜索按钮 |
| 多个可信候选 | “找到多个版本，请选择适合当前音频的歌词” + 选择按钮 |
| 服务暂时不可用且无旧内容 | “暂时无法连接歌词服务” + 重试 / 搜索 |
| 在线失败但原歌词可用 | 保留原歌词，来源旁轻提示“在线查询暂时不可用” |
| 限流 | 显示可重试时间，尊重 Retry-After；不持续弹提示 |
| 高可信结果标注纯音乐 | “纯音乐，无歌词”；仍允许用户手动更换 |

网络错误、没有匹配和纯音乐是不同结果，不能统一显示“没有歌词”或将网络错误长期缓存为无匹配。

### 4.4 搜索与更换弹窗

宽窗口采用左右两栏：左侧候选，右侧正文预览；窄窗口上下排列。弹窗标题使用当前播放歌曲，用户搜索中途切歌时关闭弹窗，或明确显示“歌曲已切换”并禁用应用按钮。

```text
为“稻香”更换歌词                                  [关闭]

歌名 [ 稻香                 ]  歌手 [ 周杰伦            ]
专辑 [ 魔杰座（可选）         ]                [搜索]
当前音频 3:43

候选                               预览
稻香 · 周杰伦                      [00:12] 歌词行…
魔杰座 · 3:43 · 同步                [00:18] 歌词行…
歌名/歌手一致，时长相差 0 秒

其他专辑版本…                      [✓] 记住这首歌的选择
纯文本候选…                   [取消] [使用这份歌词]
```

- 搜索词默认来自可信标签。用户编辑的是歌词搜索词，不修改音乐源内的歌曲元数据。
- 使用歌名必填、歌手可选的手动搜索；歌手为空或时长不同的结果只能手动选择，不能变成自动高可信结果。
- 候选显示歌名、歌手、专辑、时长和同步/纯文本标识。未知时长显示“未知”，不伪装成 0:00。
- 单击候选只预览，不更换当前歌词，也不改变音频播放位置。
- 点击“使用这份歌词”才应用。默认勾选记住；未勾选时仅当前播放会话使用，不删除或覆盖之前记住的选择和偏移，切歌或重启后恢复持久选择。
- 即使手动选择时长不同的歌词，也应允许继续使用，并提供清晰的同步可能不准确说明及纯文本选项。
- 请求期间可以取消和继续播放；不会清空原歌词。
- v1 搜索最多 20 条且无分页，搜索框和缩小条件比伪造“加载更多”按钮更合适。

### 4.5 时间调整

歌词菜单打开轻量 Popover：

```text
歌词时间调整
[提前 0.5 秒]    整体延后 0.0 秒    [延后 0.5 秒]
精确调整 [0] 毫秒                  [重置]
调整只影响这首歌，不改变音频播放速度。
```

正偏移使歌词更晚出现，负偏移使歌词提前。展示与点击歌词跳转采用同一规则：`实际时间 = max(0, 原时间 + 单曲偏移)`，避免高亮对齐后点击却跳到错误位置。

偏移应用立即生效并按 `MediaKey` 保存，切到同名但不同音乐源的歌曲不共享偏移。手动更换到另一份歌词时默认重置偏移；未勾选“记住”的临时选择只保存会话内偏移，不改变此前固定选择的偏移。固定偏移不能当成对所有演唱版本的通用修复。

## 5. 技术结构

建议新增独立 `src/lyrics/` 模块，而非把 LRCLIB 做成一个 `MusicSource`。音乐源提供音频与原生歌词能力；歌词服务提供文字与时间轴，两者身份与凭据边界不同。

建议模块：

| 模块 | 职责 |
| --- | --- |
| `lyrics/provider.rs` | 在线 provider 的 lookup/search/fetch-by-id 边界；首版 LRCLIB |
| `lyrics/lrclib.rs` | HTTP DTO、状态码、节流与元数据请求 |
| `lyrics/lrc.rs` | 纯解析：时间标签、多标签、元信息与偏移，不包含网络 |
| `lyrics/matching.rs` | Unicode/标签规范化、版本与时长检查、候选排序 |
| `lyrics/service.rs` | 原歌词与在线歌词策略、缓存与用户选择协调 |
| `lyrics/cache.rs` | 正文、自动查询索引、短期无匹配缓存 |
| `app/player/lyrics_state.rs` | 当前展示内容、搜索/预览状态、请求归属与滚动 |
| `app/settings/lyrics_view.rs` | 服务开关、策略、连接、缓存与翻译设置 |

继续使用现有 `Lyrics` / `LyricLine` 作为显示模型；在外层增加来源、服务记录 ID、匹配信息、纯音乐状态及单曲偏移。缓存采用版本化 DTO，不要求 UI 状态与 HTTP 响应一对一保存。

`SourceCapabilities.lyrics` 继续表示音乐源的原生能力。不支持原歌词的源可以跳过原生请求，但必须继续进入在线查询流程。

当前歌词 `LibraryRequest` 能拒绝过期完成，但新的流程需要区别“自动加载、显式刷新、搜索、预览”，同时保留当前正文。搜索/预览有单独请求 ID，不能用搜索结果直接填充正在播放状态。

网络客户端独立创建与复用，只携带歌词服务所需请求头。发送公开歌曲元数据，不发送音乐源 URL、账号名、Cookie、凭据或音频。LRCLIB 的 User-Agent 需要真实应用标识；匿名访问不等于无需客户端标识。

## 6. 缓存、请求与故障控制

### 缓存

- 内容缓存键为服务身份、记录 ID 和正文版本/校验值；同一份公开歌词可以复用下载内容。
- 自动查询索引包含规范化歌名、歌手、专辑、版本和时长，以及匹配算法版本，防止标签修改后沿用旧匹配。
- 用户固定选择、查询词、显示模式和偏移按 `MediaKey` 保存，不按只有歌名的字符串保存。
- 自动成功缓存建议 7 天后允许刷新；固定选择的正文保留到用户解除选择。
- 完整查询后的无匹配负缓存建议 6 小时。手动搜索或刷新可绕过负缓存。
- 超时、429、5xx 不写成无匹配。缓存读取失败可以重新获取，不影响音频播放。
- 自动缓存建议有 50 MB 的可回收上限，固定选择所引用的正文不被自动淘汰；原型里的统计数字不代表实际占用。

### 请求

- 只为当前播放歌曲查询。首版不扫描整库、不为每一首预加载曲目获取歌词。
- LRCLIB 请求顺序执行，相邻请求间隔至少 300 ms；新歌到来时取消当前过时 HTTP Future，移除队列中的旧歌查询。
- 歌曲切换、停止、服务或连接设置变更会更新请求归属；A→B→A 的第一轮 A 响应也不能覆盖第二轮 A。
- 原生歌词总预算建议 5 秒，在线流程总预算建议 8 秒；网络预算含重试与排队，候选预览可读取已经返回的正文。
- 加载不会阻塞音频起播。同一首歌刷新或更换时保留当前歌词直到新结果可用；切歌时立即解除旧歌词与播放位置的关联，不能将上一首的歌词显示成新歌的歌词。没有内容时使用页内状态。
- 429/503 遵守 Retry-After 并加少量随机抖动；等待超出当前请求预算时结束本轮展示，记录服务冷却，后续用户重试也不绕过服务限流。
- 单曲失败不触发音乐源掉线、账号失效、音频重连或跳曲。

## 7. 分阶段实施

| 阶段 | 内容 | 完成条件 |
| --- | --- | --- |
| A：基础接入 | LRCLIB v1、LRC/纯文本解析、来源模型、自动补缺与缓存、独立网络路由 | 不支持歌词的源可以获得高可信在线歌词；原播放与原生歌词正常 |
| B：用户纠错 | 搜索弹窗、候选预览、明确应用、按单曲记住、恢复自动、纯文本显示 | 原歌词错误时可手动修正；取消操作无副作用 |
| C：交互完整 | 时间偏移、设置与状态文案、窄窗/深色/中英繁体、限流取消与回归验证 | 显示和歌词跳转对齐，快速切歌与服务失败不影响播放器 |

首版应包含 A–C，不能仅以“请求 API 成功”作为完成。后续另行评估第二个服务、每个音乐源的策略覆盖、本地 LRC 导入、单独翻译服务和逐字歌词；不在本次默认引入歌词上传或外部平台修改。

## 8. 验收用例

1. Navidrome 原歌词正常：推荐策略不额外访问在线服务，手动更换入口仍存在。
2. 音乐源无歌词或请求失败：在线可用则显示，否则准确区分无匹配与服务不可用。
3. Bilibili 缺少歌手：引导搜索，不把 UP 主当歌手，不自动显示错误同步歌词。
4. 原歌词内容错误：搜索、预览、应用并记住，新一轮自动请求不覆盖选择。
5. 中文、繁体、英文大小写及日文标签：正常发送 UTF-8 查询，未知别名可手动修正。
6. 同名歌曲、Live/Remix/伴奏、时长不同或时长为 0：不自动混用版本。
7. LRC 多时间标签、毫秒精度、元信息、空行与偏移：解析正确；异常文件不导致崩溃。
8. 时间调整后，歌词高亮与点击跳转使用同一个偏移；纯文本没有时间轴操作。
9. A→B→A、停止后重播、搜索中切歌：拒绝旧结果，过时网络任务可以取消。
10. 离线重播固定歌词、清自动缓存、重启程序：个人选择及偏移按设计保留。
11. 服务关闭：没有新第三方请求；本地固定歌词仍可显示。
12. 429、503、非 JSON 错误、超时：遵守限流，不误判为没有歌词，不弹音频重连 Toast。
13. 歌词服务直连/系统代理/指定代理：可独立于音频源选择路由，保存失败不修改 live 状态。
14. 窄窗口、深色与三种界面语言：候选、预览和按钮可访问；键盘能搜索、切换候选、应用与取消。
15. 查找期间播放、暂停、Seek、自动切曲：播放器行为与没有在线歌词功能时一致。
