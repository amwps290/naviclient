# 歌词内联时间微调 设计

日期：2026-11-16
状态：已实现；自动化验证已完成，尚未在运行中的应用里验证（见“验证”）

## 背景

提交 e50d6e6 加入了拖拽式的歌词时间调整对话框（`src/app/player/lyrics_timing.rs`）。评审发现三个结构性问题：

1. 拖拽不是时间轴。行高固定 76px，映射却是固定 10 ms/px；偏移由被钳制的滚动位移推出，可调范围取决于滚动位置。
2. 模态框隔断播放。对话框打开时快捷键失效、播放栏被遮住；切歌或 Esc 会静默丢弃草稿。
3. 拖拽、±0.1 秒按钮、毫秒输入框三种方式改同一个数，单位混用；输入的值不点“应用”会在“完成”时丢失。

## 目标

边听边调：改动立即生效并保存，没有模态框、草稿和“完成/取消”。

成功标准：

- 用户在歌词面板内不离开播放就能把歌词提前或延后。
- 偏差几秒以上时，一次点击就能对齐。
- 偏移不为 0 时，主界面看得到。

## 设计

### 1. 入口与微调条

“⋯”菜单的“歌词时间调整”由打开对话框改为开关微调条，仅当显示的歌词是同步歌词时可用，打开时显示勾选状态。

微调条位于歌词头部来源信息行下方，共两行：

```text
[−0.5] [−0.1]   延后 0.3 秒   [+0.1] [+0.5]        [点击歌词行对齐] [重置] [×]
调整只影响这首歌。
```

- 中间文字是当前状态：偏移为 0 显示“已同步”，负值显示“提前 X 秒”，正值显示“延后 X 秒”。X 按偏移的实际精度显示，至少一位小数（0.3、1.23），不做四舍五入，所以显示值始终等于保存值。
- 状态文字占固定宽度，数值变化时两侧按钮不移动。宽度由 `style::tokens` 定义；极长偏移省略显示，悬停可查看完整数值。
- ± 按钮的悬停提示是“提前 0.5 秒”这类文字，说明符号的含义。
- 第二行是说明文字，始终占一行；进入对齐状态时换成对齐提示，歌词列表不会因此上下移动。提示区由设计 token 固定高度，溢出的文案省略显示，悬停可查看完整提示。
- “重置”在偏移为 0 且没有 `timing_edits` 时禁用。
- “×”收起微调条。
- 面板较窄时，右侧三个按钮换到下一行；极窄时 ± 按钮组也可以换行，不会溢出。
- 微调条收起且偏移不为 0 时，来源信息行追加 `· 延后 0.3 秒`（或“提前”），点击该文字打开微调条。
- 切歌、停止播放、歌词变为非同步（例如切到纯文本显示）时，微调条自动收起；回到原来的歌不会自动重新打开。同一首歌重复播放时保持打开。

### 2. 点击歌词行对齐

- 按下“点击歌词行对齐”进入一次性对齐状态，按钮呈选中态，说明行换成提示“在一句歌词开始唱的瞬间点击它，按 Esc 取消。”
- 对齐状态下点击有时间戳的歌词行，不跳转播放，而是设置：

  `offset_ms = 当前播放位置(ms) − 该行未加偏移的开始时间(ms)`，取整到 10 毫秒

  随后自动退出对齐状态。未加偏移的时间取自 `Document::edited_lyrics()`（含逐字修正），不从显示时间反推，避免显示时间在 0 处被截断后算错。取整到 10 毫秒是因为点击本身达不到更高精度，且显示最多两位小数。
- 对齐状态下歌词列表停止自动跟随，并保留进入状态时的活动行排版（字号、内边距和逐字布局），鼠标下的那一行不会在点击前移走；鼠标悬停的行有底色，标出将要对齐的是哪一行。播放位置继续更新，退出对齐状态后恢复当前活动行和跟随。
- 再按一次按钮、按 Esc、收起微调条、切歌、离开正在播放页、打开歌词搜索对话框都会取消对齐状态。Esc 只取消对齐，不同时关闭其他界面。
- 非对齐状态下点击歌词行仍然跳转播放。
- 一次点击算一次尝试：即使保存失败，也退出对齐状态。

### 3. 数据流

`LyricsState`（`src/app/player/lyrics_state.rs`）提供两个入口，保存规则相同：

- `change_display`：改显示方式（纯文本），之后从顶部重新跟随。`NavidromeApp::change_lyrics_display` 调用它。
- `change_timing`：只移动时间，不重置滚动位置。

  原来的 `apply` 每次都把列表滚回顶部再滚回当前行。对话框只在“完成”时触发一次；内联微调每点一下都会触发，所以时间类改动单独走这条路径。

跟随由 `lyrics.rs` 的 `follow_lyrics` 更新：对齐期间暂停滚动，并设置 `follow_resume`；退出后重建当前行的居中目标，即使仍在同一句内也会继续滚动，不把视口重置到顶部。切歌或显示方式变化的 `reset_follow` 会清除恢复标记。

保存规则（两者共用）：

- 按 `MediaKey` 写入 `LyricsCache`，写入后立即可读，落盘由缓存后台合并。
- 自动匹配的歌词只保存显示偏好，不固定内容。
- 临时选择的歌词（`temporary`）不写缓存，此前记住的选择和偏移不变。
- 进行中的歌词刷新会被取消：它开始时读到的是旧偏移。
- 保存失败时不应用改动，提示“无法保存歌词”。

微调条（`src/app/player/lyrics_timing.rs`）：

- `TimingBar { media, aligning, display_line }` 放在 `LyricsUi::timing`。`media` 记录微调条属于哪首歌，为 `None` 表示收起；`aligning` 只在打开时可以为真；`display_line` 在对齐期间保留活动行排版，避免播放跨行引起行高变化。每帧由 `sync_lyrics_timing` 校对：歌曲变了或歌词不再同步就收起，离开正在播放页就取消对齐。
- 微调条的每个控件只发出一个 `TimingAction`（`Nudge(ms)`、`ToggleAlign`、`Reset`、`Close`），由 `TimingBar::perform` 执行；歌词行点击由 `TimingBar::align_click` 判断是对齐还是交还给跳转。两者都只依赖 `LyricsState` 和 `LyricsCache`，不依赖应用对象。
- 渲染函数 `timing_bar` 对宿主视图是泛型的，应用和测试用的是同一份。
- `timing_escape` 在 GPUI 动作分发前拦截对齐状态下的 Esc，阻止该按键继续关闭菜单或触发应用快捷键。快捷键录制仍优先；没有等待对齐的点击时，Esc 按原有规则处理。应用与测试共用这份订阅逻辑。
- 偏移计算 `align`、`reset`、`adjusted` 和状态文字 `shift_label` 是纯函数。

### 4. 删除

- `lyrics_timing.rs`：`TimingEditor`、`TimingDrag`、预览列表、对话框渲染与保存、拖拽相关方法，及对应测试。
- `lyrics_search.rs`：`LyricsDialog::Timing`、`LyricsUi::offset` 输入框及其订阅、`apply_lyrics_offset_input`、`open_lyrics_dialog` 与 `sync_lyrics_dialog` 中的时间编辑分支。`LyricsDialog` 只剩 `Search`，枚举保留。
- `lyrics_view.rs`：`render_lyrics_dialog` 开头的 Timing 分支。
- `locales/{en,zh-CN,zh-TW}.yml`：删除 14 条只被对话框使用的文案，新增 6 条微调条文案。

### 5. 不在范围内

- 调偏移的键盘快捷键。
- `src/lyrics/lrc.rs` 中 `[offset]` 标签的符号问题（独立 bug）。
- `set_word_start` / `TimingEdits` 逐字编辑代码：没有生产调用方，保持不动。
- 精确毫秒输入。

## 测试

`lyrics_state/tests.rs`（7 个新增）：

- 时间改动立即显示并保存，自动匹配的歌词不被固定。
- 已记住的选择在调整后仍然固定，偏移更新。
- 临时选择只在会话内调整，记住的偏移不变。
- 时间改动不动滚动位置；显示改动从顶部重新跟随。
- 时间改动取消以旧偏移开始的刷新。
- 没有歌词文档时不保存任何内容。

`lyrics_timing/tests.rs`（替换原有拖拽测试）：

- 对齐：点击行从播放位置开始；唱得比时间戳早时偏移为负；替换而不是累加已有偏移（含显示时间被截断在 0 的情况）；取整到 10 毫秒；使用逐字修正后的时间；无时间戳或不存在的行不改动。
- 重置清除偏移和逐字修正。
- 状态文字：方向用文字表示，小数位数与偏移一致；未偏移时不显示数值。
- 微调条状态：切歌后收起且返回时不恢复；歌词不再同步或停止播放时收起；离开页面取消对齐但保留微调条；微调条收起时不能进入对齐状态。
- 动作：微调累加并保存；重置；对齐开关；关闭后偏移保留；对齐点击只生效一次，之后的点击交还给跳转。
- 界面（无头 GPUI，点击真实按钮）：四个 ± 按钮各自的步长；重置；未调整时重置按钮无效；对齐按钮开关；关闭按钮。
- 对齐期间保留进入时的活动行排版，前奏时进入也不会随后放大第一行。
- 窄、正常和宽面板切换对齐提示时列表起点不变；偏移长短变化不移动 ± 按钮。
- 对齐中打开真实菜单，第一次 Esc 只取消对齐，第二次才关闭菜单；第一次不传给应用快捷键观察者。

`lyrics/tests.rs`（2 个新增，无头 GPUI、真实滚动视口）：

- 同一句内取消对齐后，立即重新建立居中目标并完成滚动，不重置视口。
- 对齐期间播放跨行，退出后跟随最新活动行。

文案由 `src/i18n_tests.rs` 守卫：三个语言文件既不缺键也没有死键。
