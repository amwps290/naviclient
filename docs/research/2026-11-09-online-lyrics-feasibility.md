# 在线歌词服务可行性验证

日期：2026-11-09。使用场景：中文与外语混合曲库，音乐源可能没有歌词或提供了错误歌词。

设计方案：[在线歌词功能方案](../plans/2026-11-09-online-lyrics.md)。

## 结论与边界

建议首个服务接入 LRCLIB。已经实际验证公开 API 可以检索中文、英文、日文歌曲，并获取逐行同步歌词；精确查询与按记录 ID 获取也已验证。

本次验证的是接口、返回字段与候选覆盖情况，没有逐首播放音频核对歌词内容或时间轴。选取的都是较知名歌曲，不能由六首样本推断整个曲库的覆盖率，更不能保证翻唱、现场或冷门歌曲的同步效果。

## 官方接口依据

读取并核对了 [官方 API 文档](https://lrclib.net/docs.md) 和 [官方项目 README](https://github.com/tranxuanthang/lrclib)。以下为本次读取时的规定：

| 项目 | 确认内容 | 对实现的影响 |
| --- | --- | --- |
| 访问 | 支持匿名访问，无需 API Key | 用户不用注册账号即可启用 |
| 客户端身份 | 请求应带应用名、版本、项目地址或联系邮箱的 User-Agent | 正式实现补全项目公开地址；注册应用是可选项 |
| `GET /api/get` | 歌名与歌手必填，专辑与时长可选但推荐 | 使用可信歌曲元数据；验证返回记录 |
| 时长 | 提供时长时，文档描述匹配容差为 ±2 秒；参数允许 1–3600 秒 | 不用长视频总时长、未知时长或猜测值自动匹配 |
| `GET /api/search` | 支持结构化字段或 `q`；`q` 优先，最多 20 条，无分页 | 搜索结果展示与本地排序；20 条不等于总共有 20 条 |
| `GET /api/get/{id}` | 通过稳定记录 ID 取得歌词 | 支持记住用户选择与后续刷新 |
| 文本 | 返回 `plainLyrics`、LRC 格式的 `syncedLyrics`、`instrumental` 等字段 | 首版复用逐行同步与纯文本显示 |
| 扩展格式 | 当前文档另有 `lyricsfile`、`hasWordSync` | 首版不依赖逐字时间轴或 YAML 格式 |
| v2 搜索 | `/api/v2/search` 返回不含歌词文本的摘要，但仍是 beta | 首版采用稳定 v1；未来再评估升级 |
| 请求节流 | 建议顺序请求，请求之间间隔 200–500 ms | 按当前歌曲查询，取消过时请求，不扫描整库 |
| 限流 | 429 附带 `Retry-After`；额度按识别方式不同且可变 | 遵守冷却时间并加少量抖动，不写死“无限调用” |
| 无匹配 | 404；后台获取可能令记录稍后出现 | 无匹配使用短期负缓存，手动刷新可重试 |
| 错误格式 | 边缘限流及参数错误不一定返回 JSON | 优先检查 HTTP 状态、Content-Type 与 Retry-After |

文档当前给出约 45/90/180 次每分钟的不同 IP 额度示例，但明确说明这些数字不是 API 合约。客户端应主动节流，而非按照示例额度持续发满。

## 样本查询结果

使用 `/api/search?track_name=...&artist_name=...`，只保存用于分析的公开样本响应到 `/tmp`。此文档记录元数据，不复制歌词正文。

| 查询 | 返回数量 | 返回的候选中有同步歌词 | 部分观察 |
| --- | ---: | ---: | --- |
| 稻香 / 周杰伦 | 20（达到接口上限） | 20 | 专辑名有不同拼法；存在时长为 0 的记录 |
| 十年 / 陈奕迅 | 20（达到接口上限） | 20 | 专辑、合辑重复记录较多 |
| 平凡之路 / 朴树 | 20（达到接口上限） | 20 | 301、302、305 秒等版本并存，包括现场专辑 |
| Hello / Adele | 20（达到接口上限） | 20 | 歌手字段有重复写法，293 与 296 秒版本并存 |
| Never Gonna Give You Up / Rick Astley | 20（达到接口上限） | 20 | 前几条候选时长为 207–218 秒，不能无条件使用首条 |
| Lemon / 米津玄師 | 20（达到接口上限） | 20 | 256 与 274 秒版本并存；同专辑存在不同歌词行数 |

额外使用繁体歌手名“周杰倫”检索《稻香》，返回 20 条，其中 19 条有同步歌词。这只说明本样本可通过该写法查询，不代表服务自动处理所有简繁体或中外文别名。

### 精确查询与 ID 查询

以下请求已经实际完成：

| 请求 | HTTP 结果 | 观察 |
| --- | --- | --- |
| `get`：稻香 / 周杰伦 / 魔杰座 / 223 秒 | 200 | 返回记录 6716674，含同步歌词 |
| 相同元数据，但时长改为 233 秒 | 404 | 与文档的时长筛选行为一致；该 404 是测试预期 |
| `get/6716674` | 200 | 返回同一记录，元数据与同步歌词字段一致 |

三次请求的单次耗时约 0.87、1.03、1.92 秒，仅供设置交互预算参考，不是性能基准或服务可用性承诺。

可复现示例：

```sh
curl --get 'https://lrclib.net/api/search' \
  --data-urlencode 'track_name=稻香' \
  --data-urlencode 'artist_name=周杰伦'

curl --get 'https://lrclib.net/api/get' \
  --data-urlencode 'track_name=稻香' \
  --data-urlencode 'artist_name=周杰伦' \
  --data-urlencode 'album_name=魔杰座' \
  --data-urlencode 'duration=223'
```

## 与现有项目的衔接

- [歌词加载入口](../../src/app/player/lyrics.rs) 当前在音乐源不支持歌词时直接清空。因此不能只增加一个 provider 调用，而需要让在线查询独立于音乐源的原生歌词能力。
- [歌词状态](../../src/app/player/lyrics_state.rs) 已通过请求 ID 排除过期结果，但当前同曲缓存命中会抑制新加载，且开始加载会清掉旧内容。手动更换需要独立搜索/预览状态与显式刷新意图。
- [播放页](../../src/app/player/now_playing.rs) 已有同步高亮、滚动、点击时间戳跳转与翻译显示，可以保留其主体。
- [歌词数据模型](../../src/models/media.rs) 已有文本行和毫秒时间戳，但没有服务来源、候选匹配信息、持久选择与单曲偏移。
- [Bilibili 曲目信息](../../src/source/bilibili/library.rs) 当前保存视频标题、分 P 标题和 UP 主，并不提供可信歌手信息。视频标题不能默认当作标准歌名，UP 主不能当作演唱者。
- [网络路由](../../src/models/network.rs) 在本次检查时已支持系统代理、直连与保存的代理。歌词服务应复用这些路由，但单独选择连接方式。

## 服务选择建议

首版选择 LRCLIB 的依据是已验证的公开接口、同步歌词数据和无需用户密钥的使用方式。其他服务预留适配边界即可，不将多服务串行轮询作为首版默认。

Musixmatch 官方文档入口在本次环境中连接超时，未完成当前套餐、歌词展示或缓存条件的核对，因此不将其作为已验证的替代方案。后续若需要提高覆盖率，可单独评估有正式接口和明确使用条件的服务；不把未核实的平台接口写成可靠依赖。
